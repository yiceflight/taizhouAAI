# 江苏省泰州环境监测中心智能监测系统

江苏省泰州环境监测中心智能监测系统 是一个 Tauri 2 + React + TypeScript 桌面客户端。通过 Chrome 插件复用江苏大气站登录态，查询泰州市 K⁺ 小时数据，写入本机 SQLite 数据库并在主界面展示。另保留三个业务网站的网页快照报告功能。

## 小时监测

1. 启动客户端，在 Chrome 扩展管理页重新加载随客户端附带的兼容版本桥接插件。
2. 点击「江苏大气站」，完成平台登录并保持网站打开；地图页即可。
3. 首页按图表当前时间范围点击刷新按钮补齐数据，或等待后台自动检查（每 5 分钟）。

固定查询泰州市（城市口径）、K⁺ 与 PM2.5 小时混合数据。以北京时间的数据小时为唯一键，重复查询更新原记录；缺测保留为空，不写成 0。首次导入最近 7 天，图表刷新按所选时间范围重查并补齐数据库缺口；后台自动同步继续按 48 小时回查，离线后的积压按 7 天窗口续传。

主界面显示最新值、最新数据时间和最近 168 条小时记录，数据库保存全部已同步历史。运行期间可暂停自动同步；关闭窗口仍在后台运行，完全退出客户端或 Chrome 后停止查询。会话失效时需重新登录。详见 [小时监测同步](docs/hourly-monitoring.md)。

## 超标巡查计划

最新有效小时的 K⁺ 或 PM2.5 任一指标超过所设阈值时，按配置航线填写司空巡查计划；默认由工作人员确认，选择自动执行后按延迟策略提交。天气用于任务记录和风向选线，是否允许起飞由大疆后台决定；App 仍检查禁飞时段，同一来源小时不重复触发，过期或两项均缺测的数据不触发。详见 [司空计划准备](docs/flight-plan-preparation.md)。

## 飞行结束后的 Word 快报

在「报告列表 → 巡飞 Word 快报」读取可飞已结束任务，选择同一航次的司空 Immediate-Media 文件夹，生成包含照片、完整 PM2.5 序列统计与航迹图的 DOCX。媒体上传完成后，只有北京时间今天的任务会自动采集并生成；历史任务通过行内「生成报告」按钮手动下载素材和生成。自动巡查使用 K⁺ 或 PM2.5 任一指标超过设置阈值的规则，PM2.5 默认阈值为 30 μg/m³；报告保存实际执飞统计时窗、有效/缺测点数与统计结果；历史航次补生成时，城市分析仍使用生成当天的数据。报告和原始采样资料保存在本机，可重复生成并打开历史版本。模板随客户端打包，无需 Python 或桌面模板。司空计划执行状态会自动监测。

具体使用步骤、采集上限和校验规则见 [飞行结束 Word 快报](docs/flight-report.md)。

## 工作准备与界面

连接兼容版本插件后按能力验证网站：江苏大气站就绪即可开始监测，起飞依赖司空，完整报告依赖司空和可飞，照片报告仅依赖司空。历史报告可在未配置时查看。详见 [工作台流程与验证边界](docs/workspace-flow.md)。

项目结构、模块边界、环境入口和检查命令统一见 [文档导航](docs/README.md) 与 [项目结构与运行边界](docs/architecture.md)。按日期命名的验收和字段审计文档只作为历史证据。

## 开发版与正式版插件

运行 `npm run dev:client` / `pnpm tauri dev` 时，会先自动结束占用前端开发端口 1450 的进程，再继续启动；3 秒内未释放则强制结束。设置 `TAURI_DEV_HOST` 时也会清理 HMR 端口 1451。`pnpm dev` 使用相同的端口清理逻辑。

`pnpm dev:client` / `pnpm tauri dev` 使用独立测试环境：应用标识 `com.taizhou.aai.dev`、桥接端口 `127.0.0.1:14521`、独立数据库/日志/报告。首次启动为空白，不复制旧正式目录的数据或登录状态；测试版不注册自动更新插件，也不访问正式更新服务。所有平台页面、扩展管理页和后台任务都使用当前系统 Chrome；加载 `extension-dev/` 后，开发版客户端会复用你已有的登录状态。

`pnpm build:test-client` 构建可安装测试版（`--config src-tauri/tauri.test.conf.json --features test-environment`）；测试资源与安装标识必须同时使用，构建会拒绝混用。普通 `pnpm tauri build`（含 `--debug`）仍为正式版，保留 `com.taizhou.aai`、端口 `14520`、正式插件和原更新地址。不要把普通 debug 安装包当作隔离测试版。

插件源码统一修改 `extension/`；开发构建自动生成独立 ID 的 `extension-dev/`，重新编译后在当前 Chrome 中重新加载。正式版与测试版仍通过应用标识、端口和插件 ID 区分，浏览器页面统一复用当前 Chrome。环境边界及验收见 [开发与测试环境隔离](docs/environment-isolation.md)。

客户端升级后若插件版本不兼容，会显示不可关闭的强提醒并阻断采集和监测；需在 Chrome 扩展管理页重新加载对应插件。兼容要求由 `bridge-config.json` 的 `minimumExtensionVersion` 标记随客户端构建携带，详见 [在线升级](docs/updater.md)。
