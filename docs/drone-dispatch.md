# 无人机状态与巡飞调度

顶部右侧显示后台持久化任务：待命、倒计时、准备中、待人工确认、提交中、起飞请求已提交、结果待核查、取消或失败。秒级倒计时只负责显示，调度在 Rust 后台执行；关闭主窗口不会停止后台，完全退出后重启会取消旧倒计时，不补发过期起飞任务。

没有待处理任务时，有效 K⁺ 超过当前设置阈值会将右上角控件显示为与图表超标柱相同的红色（`#b44831`）。手动模式显示“需要执行任务”和“执行任务”按钮；工作环境或天气不满足时保留提醒并禁用起飞。自动起飞任务创建后显示真实倒计时与“取消任务”，取消入口不受其他操作忙碌状态影响。已取消或已提交的任务仍保留其实际结果，不因当前超标重新显示待执行提醒。

## 配置和触发

- 需要浏览器插件 v0.7.1。旧自动填写设置不迁移为自动起飞授权，自动巡飞初始关闭，可从顶部或巡查任务开启。
- 阈值、起飞延迟、人工确认共用 `workspace_settings`，无第二套延迟设置。默认 K⁺ 阈值 1.0，自动起飞延迟 5 分钟，需要人工确认；仅关闭人工确认时启用延迟，支持 0–1440 分钟。
- 成功同步/首次开始工作后，最新非未来且不超过 3 小时的 K⁺ 严格超过配置阈值，并且工作环境与天气通过时，自动起飞模式创建倒计时；人工确认模式不延迟，直接准备计划。PM2.5 不参与巡飞触发。
- 连续超标只触发一次，有效正常值重新允许下一轮。缺测不重置，同小时去重持久化。取消任务不会被下一次同步立即重建。
- 延迟在创建事件时固定；修改延迟用于下一次任务。改为人工确认会跳过已有倒计时。自动任务准备完成后、提交前再次读取最新人工确认设置：需要人工确认时只到 `ready`，由工作人员在司空确认。
- 手动起飞无需 K⁺ 超标或存在有效 K⁺ 数据，但仍需工作环境与实时天气通过，使用同一固定东南航线/机场。填写演练始终不提交。

## 取消、提交和恢复

- 倒计时和计划准备阶段可以取消；取消不被正在执行的数据同步阻塞。原生状态锁保证取消和提交只有一方成功。
- 关闭自动巡飞会取消尚未提交的自动任务。进入提交阶段后由司空处理飞行操作，客户端不将“归档”当成取消飞行。
- `dji-prepare` 仍然只填写；`dji-submit` 独立校验真实任务、原草稿、固定项目、航线、机场和全部配置，回读时不覆盖人工修改，再点击唯一最终确定一次。不会自动处理未知二次弹窗。
- 插件在尝试提交前持久化事件标记，重复同一事件会拒绝。超时、回执不匹配、提交中重启均进入待核查，不自动重试。
- 只有跳转回指定项目计划列表并读到唯一计划名才显示请求已提交。**没有飞行遥测接口，不把计划回执、倒计时归零或点击成功显示成已起飞/飞行中。**

## 验证边界

Rust SQLite 测试覆盖阈值、去重、天气门控、延迟到期、取消、人工确认配置变化、手动无数据、重启与重复提交状态。Node DOM 夹具验证填写不提交、显式提交一次、拒绝演练提交和修改后的表单。前端测试及浏览器场景验证倒计时、取消、手动按钮和待核查显示。
