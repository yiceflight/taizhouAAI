# 无人机状态与巡飞调度

顶部右侧显示后台持久化任务的简要状态与“查看详情”：待命、倒计时、准备中、待人工确认、提交中、起飞请求已提交、结果待核查、禁飞仅记录、取消或失败。详细操作与回执位于监测卡片下方“巡查任务”模块；顶部入口滚动定位到该模块。失败统一提示“起飞未完成 · 待人工核验”，不从填写校验回执推断具体设备故障。秒级倒计时只负责显示，调度在 Rust 后台执行；关闭主窗口不会停止后台，完全退出后重启会取消旧倒计时，不补发过期起飞任务。

巡查任务模块统一保留标题右侧「查看任务 →」入口，操作行不再重复显示「查看任务详情」，也不提供「查看实时监测」。待核查、已提交和执飞中保留「到司空核查任务」；没有可用菜单项时不显示「更多」。

没有待处理任务时，有效 K⁺ 超过当前设置阈值会将右上角控件显示为与图表超标柱相同的红色（`#b44831`）。手动模式显示“需要执行任务”和“立即执行任务”按钮；工作环境未就绪时禁用起飞。天气未通过时显示“手动强制起飞”，打开弹窗后必须完成现场复核、勾选确认，再点击“确认强制起飞”，仅为本次手动任务覆盖系统天气判断。自动任务始终遵守天气门控。自动起飞任务创建后显示真实倒计时与“取消任务”，取消入口不受其他操作忙碌状态影响。已取消或已提交的任务仍保留其实际结果，不因当前超标重新显示待执行提醒。

起飞准备失败的任务保留手动入口，天气通过时显示“重新发起任务”，否则显示“手动强制起飞”；两者均需要弹窗确认，无需先归档。后台只接受与当前失败任务 ID 匹配的重新发起请求，保留原失败快照与本轮自动去重标记，并创建独立的手动任务。准备中、提交中、已提交、结果待核查及执飞中的任务不能被覆盖。强制起飞的现场确认时间保存在本次任务中，不修改全局设置，也不继承到下一次任务或客户端重启后的重试。

## 任务详情模块交互规则

- 每个阶段突出一个下一步操作：倒计时/准备中可取消；待人工确认到司空核对起飞；已提交、待核查或执飞异常到司空核查；执飞中到司空核查；巡飞结束核对资料并生成报告。提交中仅展示等待状态与任务详情，不提供重复起飞或归档操作。
- 准备失败提示人工核验电量、设备和平台任务，将原始回执放入可展开详情；不把回执等同于已确认的设备故障，不以当前天气替换此前回执。未知原因不编造，详情按来源标注为触发数据时间（自动任务）或任务创建时间（手动任务）。
- 失败时主操作为重新发起（当前天气未通过时保留现场复核后的手动强制起飞），辅以「查看失败详情」和「更多」。详情及重新发起确认说明创建新手动任务、保留原失败记录，无需先归档。
- 失败任务的司空辅助入口收进「更多」，仅打开页面，不提交起飞。失败任务可选择「暂不执行本次任务」，二次确认后收起本次失败提醒；不关闭自动巡查，不清除自动任务的本轮超标去重。确认期间任务 ID 或状态变化时阻止操作。
- 已提交、结果待核查、暂停及执飞中不显示结束处理入口，继续状态核查。待人工确认的真实任务和执飞异常也持续只读核查；两者在「更多」中提供「核查后结束任务」，须勾选确认司空原计划已结束或已取消、没有待执行或正在执行的任务。结束仅解除本地占用，不取消平台计划，不标记飞行成功，不触发新的起飞。填写演练提供独立「结束演练」，不进入真实任务轮询。巡飞结束突出报告入口，新的手动任务入口放到「更多」。保存报告时不展示新任务入口。
- 待人工确认（真实任务）、执飞异常、已提交、结果待核查、暂停及执飞中的任务提供「刷新状态」，与后台自动核查共用只读查询并串行执行；不填写或提交计划。模块展示最近核查时间及失败原因，失败后可再次刷新。回执必须匹配当前事件与计划名；查询到「待执行」后从待人工确认、执飞异常或待核查转为已提交，继续跟踪并禁止重复起飞。
- 不提供单独的核查后重发入口。刷新读到本任务原草稿的明确天气阻飞且未继续执行回执后，更新为「未起飞」，保留原回执与核查记录，并恢复普通「立即执行任务」入口；本轮不自动重试，收到有效正常值后，新的超标轮次可正常触发自动任务；是否再次起飞由用户另行点击决定，仍经过原有天气和禁飞门控。手动刷新收到匹配本任务的列表回执、但仍未识别到状态时，将原待核查记录及核查原因保存到历史，解除本地占用并恢复普通起飞入口；不将原结果标记为未起飞或成功，不自动发起新任务。本轮自动触发保持抑制，正常小时数据可重新允许下一轮超标。后台轮询遇到相同情况仍保持待核查。已提交、待执行、执飞中和暂停的任务不因缺少列表行而解除；登录失效、连接超时及回执不匹配仍提示核查失败。

## 配置和触发

- 禁飞时间默认每天北京时间 05:00–08:00，设置中可增删多段，支持跨午夜。数据小时或当前执行时间落在时段内时，超标只保存带原因的 `restricted` 记录，重复同步不重复记录；禁飞结束后不补飞该小时。倒计时跨入时段或提交前配置变化同样会拦截。仅停止本应用尚未提交的起飞，不改动平台定时任务或已提交、待核查、正在执飞的任务。手动天气覆盖不能绕过当前禁飞时段。

- 需要浏览器插件 v0.7.8。旧自动填写设置不迁移为自动起飞授权，自动巡飞初始关闭。在「监测设置 → 无人机起飞策略」中启用「超标自动巡查」并保存，才能自动创建超标任务；仅关闭「起飞前人工确认」不会开启巡查。关闭自动巡查会取消尚未提交的自动任务。
- 阈值、起飞延迟、人工确认共用 `workspace_settings`，无第二套延迟设置。默认 K⁺ 阈值 1.0，自动起飞延迟 5 分钟，需要人工确认；仅关闭人工确认时启用延迟，支持 0–1440 分钟。
- 成功同步/首次开始工作后，最新非未来且不超过 3 小时的 K⁺ 严格超过配置阈值，并且工作环境与天气通过时，自动起飞模式创建倒计时；人工确认模式不延迟，直接准备计划。PM2.5 不参与巡飞触发。
- 连续超标只自动触发一次，有效正常值重新允许下一轮。缺测不重置，同小时去重持久化。取消自动任务后，本轮不会被下一次同步立即重建；手动任务与填写演练的创建、取消不消耗也不清除自动触发标记。手动任务取消后，未被自动任务处理过的本轮超标仍可在后续同步时自动触发；此前已取消自动任务的本轮仍保持抑制。
- 自动任务在发送起飞请求前准备失败（`failed`）时，同一小时的重复同步不重试。收到比触发时间更新、非未来且不超过 3 小时的有效 K⁺ 数据后，后台将原失败快照保存到 `flight_history:<id>`，清除当前失败提醒与本轮超标标记，保留原小时的去重记录。新数据正常则恢复待命；仍超标则按当前天气、自动巡查开关、人工确认和延迟重新调度。天气不通过或自动巡查关闭时不消耗新小时，后续同步可以重新判断。缺测、过期、未来数据不解除失败；手动/演练失败、主动取消、提交中、已提交、结果待核查及执飞状态不适用此规则。
- 延迟在创建事件时固定；修改延迟用于下一次任务。关闭人工确认时，自动任务填写完计划后，司空页面右侧会显示字段核对面板；所有字段回读通过后固定等待 30 秒。倒计时期间可在面板点击“取消本次作业”，取消会落到客户端持久任务状态并阻止提交。倒计时结束后才允许唯一一次最终「确定」点击。人工确认模式仍只到 `ready`，不自动点击。
- 立即执行任务无需 K⁺ 超标或存在有效 K⁺ 数据，但仍需工作环境与实时天气通过；明确人工确认的“手动强制起飞”仅覆盖本次天气判断，使用同一固定东南航线/机场。填写演练始终不提交，也不能覆盖天气门控。
- 未出现有效 K⁺ 超标预警时，顶部的“立即执行任务”先弹窗确认，展示当前机场天气、风速、阵风、降水，以及 K⁺ 浓度、阈值和数据时间。缺测、过期或时间异常明确提示无法判断；取消不会发起任务。弹窗统一使用“确认执行任务”，并说明巡飞后还需核对资料、生成报告。确认时重新检查工作环境、天气与已有任务，等待期间条件变化会阻止起飞。

## 取消、提交和恢复

- 倒计时和计划准备阶段可以取消；取消不被正在执行的数据同步阻塞。原生状态锁保证取消和提交只有一方成功。
- 关闭自动巡飞会取消尚未提交的自动任务。进入提交阶段后由司空处理飞行操作，已提交、结果待核查及执飞中的任务不提供归档入口，继续后台核查；客户端不将收起提醒当成取消飞行。
- `dji-prepare` 负责填写并回读固定字段；自动提交路径的 `dji-submit` 独立校验真实任务、原草稿、固定项目、航线、机场和全部配置，等待 30 秒后再次回读且不覆盖人工修改，再点击唯一最终确定一次。人工确认和填写演练不下发 `dji-submit`。不会自动处理未知二次弹窗。
- 插件 v0.7.10 在最终确定后只读检测司空二次弹窗，将正文（如天气阻飞、设备名、在线天气风速）回传为具体回执，不继续点击“执行”。已进入待核查的任务也会检查同事件、同计划名的原草稿，将仍存在的弹窗原因显示在“司空核查”；保持待核查且不重试提交。客户端天气源与司空天气源分别保留，客户端天气通过不能代表司空允许执行。
- 插件在尝试提交前持久化事件标记，重复同一事件会拒绝。超时、回执不匹配、提交中重启均进入待核查，不自动重试。
- 只有跳转回指定项目计划列表并读到唯一计划名才显示请求已提交。插件 v0.7.5 随后在独立的司空计划列表标签页轮询同名任务：检查「未完成」和「已结束」页，明确显示「执行中」才更新为正在执飞，「执行成功 (9/9)」等成功状态才自动恢复待命；暂停、挂起、部分执行、失败和终止保留待核查并继续轮询，后续明确执行结果仍可更新；异常也可经人工核查后结束本地处理。客户端重启后继续核查仍未归档的已提交任务。网页缺行、登录失效或状态不唯一时维持原状态并在巡查任务中显示核查原因，下一轮继续尝试，不推断飞行结束。这里显示的是司空计划执行状态，不是飞行器遥测。
- Word 快报仍需在巡查任务页核对可飞任务与司空照片后手动生成。实际保存期间顶部显示「正在生成报告」，保存结束后恢复待命；飞行结束本身不代表报告已生成。

## 任务历史与结束处理

- 自动新任务、手动新任务、失败重试和禁飞记录替换当前任务前，统一在同一 SQLite 事务内保存旧事件。新任务写入失败时，历史写入和当前状态同时回滚。
- 「暂不执行本次任务」「核查后结束任务」「结束演练」保留原状态、错误回执、天气证据，并记录结束处理时间 `resolvedAt`；任务列表显示「已结束处理 · 原状态」。不会用 `dismissed` 覆盖原来的执行结果。
- 后端结束命令同时校验事件编号、弹窗打开时的状态和确认标记。已提交、待核查、正在执行、暂停及正在提交的任务不能通过结束命令解除占用；界面状态变化时禁用原确认操作。
- 结束真实待确认/异常任务后抑制本轮自动触发，有效正常小时数据可重新允许下一轮。结束演练及收起准备失败提醒保留原有轮次规则。
