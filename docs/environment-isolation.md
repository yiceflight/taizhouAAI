## 使用

1. `pnpm dev:client` 启动开发客户端。直接 `pnpm tauri dev` 也会在创建窗口、路径和业务状态之前切换为测试身份。
2. 在运行环境异常弹窗中展开「安装与连接」，点击「打开扩展管理」，客户端会打开当前系统 Chrome。插件目录由该客户端显示：开发运行是 `extension-dev/`，测试安装包是包内的 `extension/`（内容来自生成的开发插件）。
3. 在当前 Chrome 中加载与客户端匹配的插件。正式版和开发版插件可通过不同 ID、端口连接各自客户端；不要让同一客户端同时连接多个同版本插件会话。
4. 当前 Chrome 中已有的平台登录状态会被所有平台页面和后台任务复用。不复制旧客户端数据库；首轮启动没有旧任务、设置及报告是预期行为，旧文件仍保留原位。
5. 测试安装包：`pnpm build:test-client`。它与开发运行共用测试目录/端口，二者任选其一运行，不能同时运行两个测试实例。

普通 `tauri build --debug` 依然是正式环境，必须使用显式测试构建命令。构建脚本要求测试 feature 和测试安装标识配套，避免测试包覆盖正式应用。测试包不产生更新签名资源，也不应运行正式发布脚本。

客户端不会创建或启动隔离的 Chrome 用户目录。测试界面区分未连接、版本不兼容和多会话；这些提示不要求切换浏览器配置。

## 隔离边界

这是本机应用和浏览器环境隔离，不是远端业务平台的沙箱。同一账号、司空项目或无人机设备仍代表相同的远端资源。需要完全隔离实际业务操作时，必须使用独立测试账号、项目及设备，或另行接入模拟服务；本次不创建或修改远端资源。

## 验证

- Rust 测试覆盖创建应用前的配置隔离、正式分支保持原配置、Chrome 用户目录参数，以及连接提示分类。
- UI 测试覆盖测试包即使使用生产构建的前端也不会自动检查、下载或提供正式更新入口；环境未确认时保持禁用。
- 本机运行验收需核对实际监听端口、进程打开的数据库、Chrome 命令行用户目录和原数据文件校验值。
- Windows 安装共存和真实业务账号操作需在目标机器单独验证。
