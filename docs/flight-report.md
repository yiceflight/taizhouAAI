# 飞行结束后生成 Word 快报

在客户端「报告列表 → 巡飞 Word 快报」中使用。客户端和 Chrome 插件需同时更新；桥接插件版本至少为 0.5.0。

1. 等待任务结束和两平台资料上传完成。可飞任务结束时间至少早于当前时间 1 分钟。
2. Chrome 登录可飞嗅探平台，在客户端选择该页面，点击「读取飞行任务」。选择同一航次，可用「加载更早任务」读取历史记录。
3. Chrome 打开指定泰州司空项目的本次任务文件夹，再进入 `Immediate-Media`，清空文件名搜索。客户端选择该媒体页。
4. 点击「生成 Word 快报」。插件按任务编号读取完整 PM2.5 序列和坐标，逐张打开司空照片预览并下载对应原始 JPEG/PNG。采集期间不要切换所选页面或任务。
5. 生成后点击「打开 Word」。也可以从「报告目录」进入 `flight/<报告编号>`，找到 DOCX、照片、`pm25-route.csv` 和 `source.json`。每次生成保留独立版本。

## 报告内容

基于用户提供的《周山河街区无人机机库智能巡飞监测快报》模板保留红色刊头、单位、正文五个章节和影像附录。模板已编译到客户端；运行时不需要 Python、Office 或桌面模板文件。

- 航次编号、起止时间、时长和位置；全部时间明确为北京时间。
- PM2.5 原始采样的有效/缺测数量、最小值、最大值、算术平均值与峰值时间；采样曲线不替代小时或日均值。
- 根据可飞采样经纬度绘制的航迹图，无地理底图，明确标注来源。
- Immediate-Media 照片清单及逐张影像，不以页面缩略图或网页截图代替。
- 原模板历史案例、历史日期、署名和历史图片不带入；未取得的 K⁺、气象、火点识别与污染成因不会推断。PM2.5 全部为零时明确提示核查传感器。

## 数据校验与边界

- 此版本由用户选择已结束任务后点击生成，尚未自动监控飞行结束或自动导航到各航次媒体文件夹。
- 司空来源锁定用户指定的组织/项目，且必须进入 Immediate-Media；通过任务文件夹时间与照片文件名中的拍摄时间核对可飞任务，允许前后 5 分钟差异。
- 当前每份报告最多 20 张、每张至多 12 MB、可飞最多 20000 个采样点。多页/搜索筛选时拒绝生成，避免悄悄遗漏照片。
- 没有照片时，只有明确空文件夹且航次匹配才能生成无照片报告。
- 可飞通过固定只读接口复用页面登录态；插件不会读取 Cookie、localStorage、口令或访问令牌。司空通过固定的当前照片记录读取下载地址，下载完成后不保留临时签名图片链接。
- 任一平台未登录、数据不完整、单位不符、航次不匹配、照片导出失败或连接超时，均显示具体错误；完整 DOCX 和资料以临时目录写入后原子归档。
- 司空或可飞改版可能需要更新固定页面适配器。没有自动 AI 火点判读；正式签发前需复核。

## 维护与验证

模板构建脚本 `scripts/prepare-report-template.py` 仅用于开发，输入用户原始模板，输出 `src-tauri/assets/flight-report-template.docx`。正式运行使用 Rust ZIP/OOXML 写入。

运行 `pnpm test`、`cargo test --manifest-path src-tauri/Cargo.toml` 和 `pnpm build`。打包本地验收使用 `pnpm tauri build --debug --bundles app --config '{"bundle":{"createUpdaterArtifacts":false}}'`，不产生发布签名或更新清单。真实验收必须在原生客户端使用已登录两平台完成生成，再检查实际 Word 排版。
