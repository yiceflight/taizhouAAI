# 飞行结束后生成 Word 快报

刊头外层期号和「泰智飞」系列期号均按实际起飞时间（北京时间）生成，格式为 `YYYYMMDDHHmm`。例如2026年11月8日09:00起飞，对应「第202611080900期（泰智飞 第202611080900期）」。同一航次重新生成时仍使用该起飞时间；已有Word文件需重新生成才会采用此规则。

在客户端「巡查任务」中使用。客户端和 Chrome 插件需同时更新；当前客户端要求桥接插件 0.7.38 或更新版本，更新后需在 Chrome 重新加载。

客户端保持运行且司空验证通过时自动同步司空“已结束”任务，不受当前客户端页面影响；首次启动约 5 秒后开始。插件复用已登录的泰州项目页，向司空中国区任务接口发送只读 GET，每页 50 条，不切换页面的列表、筛选或分页。每次刷新最新一页，历史每批最多再读取 5 页，保存游标后约 5 秒续读；全量结束后每轮间隔 60 秒刷新最新任务，历史每 6 小时重扫。历史总数变化时重新扫描，失败保留已收到的任务及待重试页；历史同步正常进行时先完成同步，再自动采集照片。

任务以司空任务 UUID 去重、持久化，保留实际开始、结束时间及原始执行结果。为兼容既有报告，时间仍按分钟展示和关联。平台缺少实际结束时间但已有实际开始时间时，列表保留开始时间并标出结束时间待确认；完全缺少实际时间时按司空任务日期归组。计划时间只用于归组和定位，不代填实际飞行时间，也不自动生成报告。升级时以接口记录替换原先同一航次的列表记录，既有报告文件不变。

任务列表固定每页 50 条，支持上一页、下一页、页码和跳页；同步或自动生成报告期间也可翻看已加载任务、打开已有 Word/文件夹及进入生成弹窗；刷新只限制重复读取，不锁住整张任务列表。清空任务列表之前的记录默认隐藏，可点击「显示历史任务」查看，查看历史不会改变自动报告的清空时间界限。「同步更多可飞历史任务」独立读取可飞的下一批任务。

任务同步复用现有项目页，不再创建共享媒体页。每个报告任务在后台创建一个独立的司空媒体页，按任务 UUID 绑定，每轮最多串行处理 3 个报告；任务完成、失败或超时后只关闭插件创建的媒体页，用户原本打开的司空页面不会关闭。巡飞状态查询共用一个计划页，不按每个任务新建状态页。天气查询仍使用专用后台页，任务草稿保留。

媒体上传结束且飞行结束至少 1 分钟后，队列每轮处理最多 3 个**北京时间今天**待生成或待补齐报告的任务，按上次尝试时间轮转。昨天及更早的任务不会进入自动采集队列，仍保留列表中的「生成报告」按钮，由工作人员手动下载素材并生成报告。外部每日同名任务按实际起止时间区分；与可飞和本地记录唯一匹配时合并成一行。完整报告复用；照片报告关联到可飞采样后自动采集并保存新版本，失败保留原文件且下轮重试。版本关联持久保存，重启或离线时只显示新版本，旧文件仍可追溯。首次读取本地报告列表失败也会在后续自动周期重试。没有可飞任务则自动生成照片报告、采样章节留空；已关联可飞任务时等待采样读取成功，不将平台错误默认为无数据。手动生成弹窗打开时不再启动后续自动采集；已经进行中的自动报告会完成。此时点击手动读取会显示排队，当前自动报告完成后优先执行手动请求，关闭弹窗可取消等待。任务同步提示和弹窗采集提示独立显示，迟到的刷新回执不会覆盖刚保存的新报告。司空明确返回“无媒体文件”时列表标记为“无媒体文件”，不生成报告；“上传结束”是上传完成的依据，不能因找不到 Immediate-Media 文件夹改为等待上传。没有该子目录时，读取已匹配航次的根目录，完整核对全部分页和文件数量；只有视频或已确认照片目录为空时显示“无照片”，不生成报告。存在未知文件、子目录、数量不符或不支持的图片时显示解析原因，不推断为无照片。这些结果在当前客户端会话内停止自动重试，保留“重新读取媒体”入口；媒体目录或上传数量改变时重新自动评估，重新打开客户端也会重新核验当天任务。媒体列显示司空返回的已上传数/应上传数。

“打开 Word”右上角红色角标表示问题数量：从 Immediate-Media 的图片文件名读取北京时间，排序后每组最早至最晚相差不超过 3 秒（含边界）算 1 个问题，例如 0、3、6 秒分成两组，避免连锁合并。零问题不显示角标。数量与原始图片总数分别保存，所有原图保留；`issues.json` 记录分组依据和每组文件名。旧报告从 `source.json` 补算，不重新下载、不修改原 Word。该角标是用户指定的照片归并统计，不改变正文中需要人工核实的影像判读。

以下为按需手动生成或重新生成流程：

1. 等待任务结束和两平台资料上传完成。可飞任务结束时间至少早于当前时间 1 分钟。
2. Chrome 登录可飞嗅探平台，在客户端选择该页面，进入「巡查任务」读取列表（也可点击「刷新任务」），在对应行点击「生成报告」打开居中弹窗，可用「加载更多任务」读取历史记录。
3. Chrome 保持指定泰州司空项目已登录即可；计划页、团队页或媒体页均可提供采集会话，无需额外打开媒体库页、手动选择航次或进入照片文件夹。客户端会为每个报告任务创建后台媒体页，任务完成后自动回收；采集期间不要手动关闭这些后台页。
4. 在弹窗点击「自动匹配并读取资料」。新生成和重新生成均携带已关联本机事件 ID，保留本机触发原因与飞行证据；优先带入已关联司空航次的实际起止时间及任务 UUID，同时保留可飞任务编号用于读取采样；不使用可飞采样的起止时间替代已确认的实际飞行时间。插件按可飞任务编号读取完整 PM2.5 序列和坐标，优先使用已持久化的司空任务媒体目录编号直接定位；没有目录编号时清空文件名搜索并遍历媒体库分页，以北京时间开始时刻前后 5 分钟查找唯一航次，自动进入 `Immediate-Media`，逐张读取原始 JPEG/PNG。未找到、多个候选、分页不完整或缺少照片文件夹会在弹窗内报错，不会任选最近一项。核对资料后点击「生成并保存 Word 快报」。采集期间不要切换平台页面或任务。
5. 生成后点击「打开 Word」查看报告，或点击同一行的「打开文件夹」，在系统文件管理器中打开该报告目录并选中 Word 文件；这两个入口无需连接平台即可使用。也可以从「报告目录」进入 `flight/<报告编号>`，找到 DOCX、照片、`pm25-route.csv` 和 `source.json`。每个任务仅对应一份报告，普通重复保存返回已有报告。「打开 Word」旁的「重新生成报告」会打开同一弹窗，重新读取资料并保存新版本，列表展示最新版本，旧文件保留；无可飞数据报告会预填已确认的任务名称和实际飞行时间。缺少任务资料的旧报告需先连接平台刷新任务。旧报告从 source.json 恢复任务关联；同一任务的旧版本在列表中仅显示最新一份，磁盘文件全部保留。表4在实际执飞起止时间内（含端点），依次选出PM2.5、PM10、SO₂、NO₂、CO最高值记录，每行展示该时刻点位经纬度和全部五项读数，当前指标最高值加粗；并列取最早时刻，零值有效，缺测不补0。`report-settings.json` 保存统计时窗、原始/时窗内点数、PM2.5有效/缺测点数及统计结果。

### 没有可飞数据时

已有可飞任务但采样读取失败时，在生成弹窗勾选「可飞数据暂不可用，相关内容留空」，再使用同一个「自动匹配并读取资料」按钮，只匹配并读取司空照片。此选择不会自动替代失败的正常采集。

有无可飞记录均使用同一生成弹窗，固定显示「飞行时间、司空照片、可飞采样」三个资料区，匹配和保存操作位于固定底栏。没有可飞任务记录时，从对应本地已完成任务点击「生成报告」，可飞采样区提示内容留空，不再展开另一套表单或大段警告。实际时间缺失时点击「补充时间」，在原资料区内补充任务名称和实际飞行起止时间（北京时间）；已有无可飞报告重新生成时显示已确认的时间，可按需修改。未补全就点击匹配会展开输入区并提示，不会发送采集请求。插件 0.7.13 起，按精确计划名读取司空计划列表的实际开始、结束时间并计算执行时长；读取日期分组及实际时间列，不取计划时间或任务发起时间。司空列表仅提供分钟精度，界面明确标注。已完成的当前任务及保留历史会自动补读并持久化，打开报告时自动带入；平台尚未给出完整时间、日期范围未覆盖或匹配不唯一时保留补充时间入口。已取得的时间不会因后续空回执而被清除。飞行结束至少 1 分钟后可读取。此模式只要求浏览器插件兼容且司空登录验证通过，无需可飞或大气站就绪、无需先开始监测。

生成的 Word 保留原模板的可飞章节和八列五参数表，保留固定的传感器及数据来源介绍，五行数据格留空，供后续手工补充；不会写入零值、推断阈值统计或触发全零传感器提醒。无可飞任务时任务编号也留空。任务时间和正文司空照片正常保留。`source.json` 和报告记录明确标记 `withoutAirData`；无可飞任务的内部 `missionId=0` 仅表示无平台编号，归档通过本地任务编号或填写的任务名称和起止时间区分，避免多个无可飞报告互相覆盖。

任务列表的编号来自可飞，不能作为司空任务 ID。任务名称符合本应用生成规范时，显示「本应用·自动巡查」「本应用·手动起飞」或「本应用·填写演练」；其他任务显示「司空平台任务」。司空同步同时读取当前计划列表行的任务类型、计划名称、航线名称、执行结果和媒体上传状态；平台未返回类型时显示「司空任务」；航线优先读取该航次的司空记录，再使用关联本机事件保存的航线，两者都缺失时显示「航线未记录」，不使用当前默认航线补写历史，不根据任务名称推断类型。任务类型优先保留平台中文名称；接口或历史缓存中的编码 `4` 显示为「自动任务」（已对照司空同一航次核实），其他未识别的数字编码显示「类型待确认」，不直接展示数字。天气只在本应用发起任务时记录创建时的天气检查；司空平台自行发起的任务不补录历史天气，列表显示「司空平台任务无需记录天气」。

## 报告内容

使用用户提供的《标准.docx》清理副本填空，不从空白文档重新排版。当前参考保存在 `src-tauri/assets/flight-report-reference.docx`，SHA-256 为 `25aa8b8df042c1f4577fc3ba0a19712dabd5a88543ff24abc75ec09c0c30b141`。刊头两处使用同一个报告序号；第二章不重复放媒体照片，第三章按表2序号分组放置照片，第四章保留空气五参数表。运行时不需要 Python、Office 或桌面模板文件。

- 使用 `fill-v8` 固定模板：保留五章、表1六列、表2六列、表4八列及原单位说明。表4采用“序号、监测时间、点位/经纬度、五参数”，列五项指标最高值所在的五条记录。模板之外不自动增加段落、附件或曲线图。
- 第一章按分析小时读取泰州市城市小时数据；历史航次补生成仍使用该航次的分析小时。PM2.5、K⁺及其比值分别取分析时刻之前（含分析时刻）最近两条有效记录，较早值与较晚值的实际日期小时会写入首段；缺测不补0，也不把旧值伪造成缺测小时。高于1 μg/m³小时数、对应时刻、K⁺峰值及同小时PM2.5分别填入独立字段。升降词按数据切换，起点为0不计算变化率；不足两条有效记录留【 】。高值过程分段规则未确定，次数和突出过程时间留空；燃烧特征仅接受完整、航次绑定的人工确认，不自动归因。第二章预留区域不重复放媒体照片，媒体照片保留在表2/附件1。
- 第二章一航次一行，只使用匹配的实际起止时间和航线。覆盖范围无确认依据则留空，不将执行成功当成完整覆盖。触发原因来自精确匹配的本机事件或已保存原因；司空任务名称和任务类型不替代触发原因。
- 表2按拍摄时间列出全部照片；经纬度来自有效EXIF，影像类型来自DJI XMP。人工判读内容优先；没有人工判读时，红外照片读取司空详情页的最高/最低温度标注，并生成“照片坐标发现红外高温点、热源性质待核实”的客观描述，同时保留相对高度。未取得温度标注时说明高温点待判读。坐标仍为WGS-84拍摄位置，不代表污染源坐标。
- 第二章不插入代表照片或点位分布图及其图注。第三章按既有3秒抓拍分组排序，每张照片单独一行，同组图片等比缩放并保持同页；图下仅写“组号-组内序号”（如1-1、1-2、2-1）；分组只是排版，不作为异常处数。保留已有照片标注合成结果，不增加历史附件。
- 表4各参数分别统计实际执飞起止时间内（含端点）的全部有效值，包含低值和零值，缺测不补0；不同参数峰值未必同刻。PM2.5时窗内无有效值时仍要求明确选择无可飞模式。缺失通道或整窗缺测在Word中留【 】；CSV及原始数据仍保留缺失状态。气体换算继续采用平台口径；CO保留3位小数，其余浓度1位。
- 第五章只填写 `report-photo-reviews.json` 中已确认的结论和建议，不再追加采样摘要或默认说明。该文件必须绑定本地事件、实际起止时间和完整原图SHA-256集合；逐图地点/描述/识别结果按哈希载入，整体判读来源、异常处数、燃烧确认、结论、建议仅在完整集合匹配时载入。新增可选字段见 [字段契约](flight-report-fill-contract.md)。没有输入时留【 】；不自动调用模型。
- 数据来源、判读来源、城市序列、传感器全零提醒和计算口径留在界面或归档，不自动加入正文。原始数据、平台曲线截图、照片及既有CSV归档继续保留。
- 原模板“举例”之后的历史文字、签审和照片不带入。生成器版本 `flight-template-fill-v8`、模板版本 `fill-v8`、参考模板哈希和统计结果记录于 `report-settings.json`。旧文件不覆盖，通过“重新生成报告”生成新版本。

### 可飞 PM2.5 原图曲线

正常采集会为该可飞任务打开独立后台历史页，展开并选择 PM2.5 时间曲线；核对完整采样首末时间、点数、最高/最低值，等待画面稳定后截图，完成后关闭该后台页。曲线仅作为归档材料，不再自动插入固定Word模板。表4仍仅统计实际执飞时段。截图与源数据不匹配、加载失败或画面变化会明确报错，不静默遗漏图表。

截图原图另存为 `airins-pm25-chart.png`（历史导入可为 JPEG），来源、时间范围、截图时间和尺寸随 `source.json` 归档。无可飞模式不插图；旧报告保持原文件，通过“重新生成报告”采集新图。新增截图需要客户端及插件0.7.29，更新插件后重新加载。

## 数据校验与边界

- 自动流程在确认实际飞行时间和媒体上传结束后采集并保存；手动流程保留弹窗核对和重新生成入口。资料读取自动导航到唯一航次媒体文件夹。
- 司空来源锁定用户指定的组织/项目，自动进入 Immediate-Media；通过任务文件夹时间与照片文件名中的拍摄时间核对可飞任务，允许前后 5 分钟差异。
- 当前每份报告最多 200 张，每张原图及其标注合成图分别至多 12 MB，可飞最多 20000 个采样点。照片列表逐页读取，并记录下载页码；超限、未知图片格式或跨页重复时明确报错，避免遗漏。航次查找最多遍历 20 页、65 秒，超出范围报错；文件名搜索在匹配前自动清空。
- 没有照片时，只有明确空文件夹且航次匹配才能生成无照片报告。
- 可飞通过固定只读接口复用页面登录态；插件不会读取 Cookie、localStorage、口令或访问令牌。司空通过固定的当前照片记录读取下载地址，下载完成后不保留临时签名图片链接。
- 正常采集时任一平台未登录、数据不完整、单位不符、航次不匹配、照片导出失败或连接超时，均显示具体错误；无可飞数据模式仍校验司空来源、航次和照片完整性。完整 DOCX 和资料以临时目录写入后原子归档。
- 司空或可飞改版可能需要更新固定页面适配器。没有自动 AI 火点判读；正式签发前需复核。

### 大疆动态标注归档（插件 0.7.29）

下载照片时，同时核对司空照片预览中的标注数量和完整原图尺寸。存在动态标注时，在本任务专用后台页捕获大疆实际渲染的照片与标注图层，保留温度点、温度文字及页面上显示的其他标注样式；不从热图颜色推算温度，也不重新绘制近似标签。截图仅含照片区域，临时隐藏可能遮挡照片的横幅、文件名和操作按钮，保留温度点等图标依赖的共享 SVG 图形定义，完成或失败后恢复。先用照片区域的实际截图测量 Chrome 的输出像素比例，再按完整合成区域的目标尺寸捕获；小数 CSS 像素取整造成的不超过 2 像素偏差，通过完整画面缩放规范到目标尺寸，不裁剪标注。比例不符或较大尺寸偏差仍报错。原图单独下载、逐字节保留。

预览和正文照片统一使用合成图；没有标注且数量核对为 0 时使用原图；司空无标注照片使用已挂载的空标签区（没有“0”徽标），插件将其识别为零标注，缺少标签区或未知非空结构仍报错。报告目录中的 `photo-N.jpeg/png` 是原图，`photo-N-annotated.png` 是合成图。`source.json` 保存两份图片以及捕获时间、标注数量和文字，`photo-manifest.json` 记录文件对应关系与各自 SHA-256；`imageRect` 记录原图在合成画布内的位置及原始像素尺寸。EXIF、GPS、相机类型和已有人工判读的照片身份始终基于原图，合成图不替代原始证据。

标注未加载完整、被隐藏、捕获期间发生变化、截图超时或尺寸不符时明确报错，不静默回退成缺少标注的图片。照片边缘的温度点按实际 SVG 图形计算范围，不使用空白外层容器；真正越界的文字、图形及描边自动增加留边。合成时照片和标注整体等比适配已有视框，保留相对位置和原图像素密度，合成画布可大于原图，无需修改大疆保存的标注。升级后重新加载插件；已有报告不会被自动改写，需要使用“重新生成报告”重新采集才能补入标注。
