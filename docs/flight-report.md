# 飞行结束后生成 Word 快报

在客户端「巡查任务」中使用。客户端和 Chrome 插件需同时更新；按时间自动匹配需要桥接插件 0.7.12 或更新版本。

1. 等待任务结束和两平台资料上传完成。可飞任务结束时间至少早于当前时间 1 分钟。
2. Chrome 登录可飞嗅探平台，在客户端选择该页面，进入「巡查任务」读取列表（也可点击「刷新任务」），在对应行点击「生成报告」打开居中弹窗，可用「加载更早任务」读取历史记录。
3. Chrome 保持指定泰州司空项目的媒体库已登录、打开即可，无需手动选择航次或进入照片文件夹；多个媒体页时客户端自动复用同一浏览器会话中的页面。
4. 在弹窗点击「自动匹配并读取资料」。插件按可飞任务编号读取完整 PM2.5 序列和坐标，清空司空文件名搜索并遍历媒体库分页，以北京时间的开始时刻前后 5 分钟查找唯一航次，自动进入 `Immediate-Media`，逐张读取原始 JPEG/PNG。未找到、多个候选、分页不完整或缺少照片文件夹会在弹窗内报错，不会任选最近一项。核对资料后点击「生成并保存 Word 快报」。采集期间不要切换平台页面或任务。
5. 生成后点击「打开 Word」查看报告，或点击同一行的「打开文件夹」，在系统文件管理器中打开该报告目录并选中 Word 文件；这两个入口无需连接平台即可使用。也可以从「报告目录」进入 `flight/<报告编号>`，找到 DOCX、照片、`pm25-route.csv` 和 `source.json`。每个任务仅对应一份报告，普通重复保存返回已有报告。「打开 Word」旁的「重新生成报告」会打开同一弹窗，重新读取资料并保存新版本，列表展示最新版本，旧文件保留；无可飞数据报告会预填已确认的任务名称和实际飞行时间。缺少任务资料的旧报告需先连接平台刷新任务。旧报告从 source.json 恢复任务关联；同一任务的旧版本在列表中仅显示最新一份，磁盘文件全部保留。PM2.5 超阈值统计使用生成时保存的报告阈值（默认 60 μg/m³，严格大于），在 `report-settings.json` 中留存本次阈值。

### 没有可飞数据时

已有可飞任务但采样读取失败时，在生成弹窗勾选「可飞数据暂不可用，相关内容留空」，再使用同一个「自动匹配并读取资料」按钮，只匹配并读取司空照片。此选择不会自动替代失败的正常采集。

有无可飞记录均使用同一生成弹窗，固定显示「飞行时间、司空照片、可飞采样」三个资料区，匹配和保存操作位于固定底栏。没有可飞任务记录时，从对应本地已完成任务点击「生成报告」，可飞采样区提示内容留空，不再展开另一套表单或大段警告。实际时间缺失时点击「补充时间」，在原资料区内补充任务名称和实际飞行起止时间（北京时间）；已有无可飞报告重新生成时显示已确认的时间，可按需修改。未补全就点击匹配会展开输入区并提示，不会发送采集请求。插件 0.7.13 起，按精确计划名读取司空计划列表的实际开始、结束时间并计算执行时长；读取日期分组及实际时间列，不取计划时间或任务发起时间。司空列表仅提供分钟精度，界面明确标注。已完成的当前任务及保留历史会自动补读并持久化，打开报告时自动带入；平台尚未给出完整时间、日期范围未覆盖或匹配不唯一时保留补充时间入口。已取得的时间不会因后续空回执而被清除。飞行结束至少 1 分钟后可读取。此模式只要求浏览器插件兼容且司空登录验证通过，无需可飞或大气站就绪、无需先开始监测。

生成的 Word 保留原模板的可飞章节和九列六参数表，监测正文和四行数据格留空，供后续手工补充；不会写入零值、推断阈值统计或触发全零传感器提醒。无可飞任务时任务编号也留空。任务时间和正文司空照片正常保留。`source.json` 和报告记录明确标记 `withoutAirData`；无可飞任务的内部 `missionId=0` 仅表示无平台编号，归档通过本地任务编号或填写的任务名称和起止时间区分，避免多个无可飞报告互相覆盖。

任务列表的编号来自可飞，不能作为司空任务 ID。任务名称符合本应用生成规范时，显示「本应用·自动巡查」「本应用·手动起飞」或「本应用·填写演练」；其他任务统一显示「司空平台任务」，不再显示「原因待核对」，也不再提供逐条下拉选择。当前插件只读取司空媒体库的 `Immediate-Media`，无法验证司空任务详情中的计划类型；因此「司空平台任务」表示来源归类，不代表已经读取到司空内部的定时/手动字段。列表读取后会按航次开始时刻自动补全并持久化 Open-Meteo 历史预报的对应小时天气，含天气现象、气温、风速、阵风、降水、数据时刻和补录时刻。未结束、数据缺失或服务不可用的任务保持「天气待补全」，下次刷新会重试。历史模型资料不代表机库现场实测，也不替代起飞前的天气检查。

## 报告内容

使用用户原始文件的副本填空，不从空白文档重新排版。原始参考保存在 `src-tauri/assets/flight-report-reference.docx`，SHA-256 为 `e30bc73f8f720df2c150e36a41a10080a3ff871be0be7cd3e9466f09c16c0a32`。运行模板保留原样式、编号、主题、字体表、红色刊头与红线、页边距、段落字号/行距、表格列宽/边框/灰色表头及科学符号下标。运行时不需要 Python、Office 或桌面模板文件。

- 保留五章原名、表1六列、表2七列、表4九列与原单位说明，不再输出“资料/本次收录”替代表格和独立照片附录。
- 第一章按生成当天北京时间00:00至生成时刻填写分析窗口。原生保存时快照读取泰州城市口径K⁺小时序列，写入首末有效浓度及各自小时、严格大于1 μg/m³的有效小时数和时刻、全窗有效峰值及发生小时，并说明有效/缺测或未发布小时数。端点缺测不冒充已有观测，0不当缺测，缺测不补0。城市PM2.5尚未接入，浓度、升幅及K⁺/PM2.5比值明确写未取得/无法计算；不用航次PM2.5或旧库PM2.5列代填。明显高值过程划分规则未定，不把小时数当过程数，不自动归因为生物质燃烧。
- 期号保留“第【 】期（泰智飞 第【 】期）”。区段、覆盖、坐标、影像类型和判读没有核实数据时保持空位或明确待核实，不复制示例航线、历史结论和签审人员。
- 航次时间和照片总数写入正文/合计。表内时间采用紧凑时分格式；跨日带日期。照片按拍摄时间排序，表2序号对应正文图注，原图保留在包内和资料归档中。
- 第二章保留现场照片及对应位置图位置，第三章收录本次全部照片。照片EXIF含有效GPS时填写WGS-84拍摄位置，并生成数字对应表2序号的离散位置图；相机类型从DJI XMP的ImageSource读取，不能只猜文件名。照片记录按“抓拍点”列出，不冒充已核实航线；完整覆盖范围仍需实际轨迹。图中不连接航迹，不把无人机GPS或激光瞄准点认定为污染源位置。任务原因从精确匹配本地事件编号和实际起止时间的记录取得。
- 正常模式将全部采样按时间逐行填入表4，PM2.5及采样坐标据实填写，其余未接入参数显示“未取得”；有效序列中的缺值标为“缺测”。无可飞数据模式保留四行空格。大量采样会自然增加页数，不静默截取、合并或抽样。
- 第五章填写已取得的采样统计或经逐图核对的本航次结论。可选本地编辑输入`report-photo-reviews.json`必须绑定本地事件、实际起止时间和每张原图SHA-256；逐图描述可按精确哈希载入，整体结论/建议仅在全部图片集合完全匹配时载入。判读来源、文字、城市序列和事件快照保存在`source.json/evidence`，不接受前端自行声称的数据依据。无采样和无影像判读时保持空位；没有自动调用图像模型，不把未经复核的亮斑写成确认火点，不用照片数代替异常处数。PM2.5全部为0时保留传感器核查提醒。
- “举例”之后的历史文字、签审信息和图片不带入；不新增页码、图表章节或附件。生成器版本 `template-fill-v3` 和模板哈希随本次阈值保存在 `report-settings.json`。旧文件保留，通过已有“重新生成报告”生成新版本。

## 数据校验与边界

- 此版本由用户选择已结束任务后点击生成。司空计划执行状态可由后台核查；资料读取会按时间自动导航到航次媒体文件夹，报告保存仍需在弹窗确认。
- 司空来源锁定用户指定的组织/项目，自动进入 Immediate-Media；通过任务文件夹时间与照片文件名中的拍摄时间核对可飞任务，允许前后 5 分钟差异。
- 当前每份报告最多 20 张、每张至多 12 MB、可飞最多 20000 个采样点。照片多页时拒绝生成，避免悄悄遗漏照片。航次查找最多遍历 20 页、65 秒，超出范围报错；文件名搜索在匹配前自动清空。
- 没有照片时，只有明确空文件夹且航次匹配才能生成无照片报告。
- 可飞通过固定只读接口复用页面登录态；插件不会读取 Cookie、localStorage、口令或访问令牌。司空通过固定的当前照片记录读取下载地址，下载完成后不保留临时签名图片链接。
- 正常采集时任一平台未登录、数据不完整、单位不符、航次不匹配、照片导出失败或连接超时，均显示具体错误；无可飞数据模式仍校验司空来源、航次和照片完整性。完整 DOCX 和资料以临时目录写入后原子归档。
- 司空或可飞改版可能需要更新固定页面适配器。没有自动 AI 火点判读；正式签发前需复核。

## 维护与验证

模板构建脚本 `scripts/prepare-report-template.py` 仅用于开发，默认读取仓库内保留的用户原始模板，输出 `src-tauri/assets/flight-report-template.docx`。正式运行使用 Rust ZIP/OOXML 写入。

运行 `pnpm test`、`cargo test --manifest-path src-tauri/Cargo.toml` 和 `pnpm build`。打包本地验收使用 `pnpm tauri build --debug --bundles app --config '{"bundle":{"createUpdaterArtifacts":false}}'`，不产生发布签名或更新清单。真实验收必须在原生客户端使用已登录两平台完成生成，再检查实际 Word 排版。

模板保真检查：使用文档工具提供的 Python 运行 `tests/report-template.test.py [生成文件.docx]`，对比原样式包、刊头红线、段落属性、五章、6/7/9列表头、上下标和历史内容清理。另运行 Rust 报告测试。DOCX须渲染逐页检查；检查环境若没有方正字体，只能验证替代字体下的布局，不能据此声称与目标 Word/WPS 的字体和分页完全一致。
