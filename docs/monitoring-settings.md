# 监测设置

工作台导航栏右侧的“设置”打开弹窗。修改后点击“保存设置”写入本机 `monitoring.sqlite3`，重启后保留；取消或 Esc 不保存草稿。航线列表同步和默认航线选择是独立即时操作，不随取消设置撤销。“恢复默认”先恢复表单，仍需保存才生效。

| 设置 | 默认值 | 行为 |
| --- | --- | --- |
| 钾离子 K⁺ 阈值 | 1.0 μg/m³ | 大于阈值才视为超标；用于卡片、图表、表格提示与巡查触发 |
| PM2.5 起飞触发阈值 | 30 μg/m³ | 位于“监测阈值”区域；大于阈值时触发巡查计划，起飞按执行策略处理；用于监测预警，与报告统计独立 |
| 超标后延迟 | 5 分钟 | 仅在关闭人工确认、自动执行时显示和生效；可设 0–1440 整数分钟；从发现 K⁺ 或 PM2.5 有效超标数据时计时；修改用于后续任务 |
| 起飞前人工确认 | 开启 | K⁺ 或 PM2.5 超标后自动创建巡查计划；开启时等待工作人员确认，关闭后按延迟自动执行 |
| 默认航线 | 司空航线列表同步后选择 | 设置中点击“同步司空航线”读取当前项目航线；选择结果按前缀传给计划填写和提交校验，平台生成的“副本”后缀兼容，精确匹配优先，前缀匹配取去空白后字符数差异最小的一条，最小差异并列时停止 |
| 风向航线规则 | 空 | 起飞需选择已同步的默认航线，可配置 0–8 条规则；选择北风、东北风、东风、东南风、南风、西南风、西风、西北风之一，每个方向最多一条，共最多 8 条；有效风向未匹配，或风向缺测、过期、无效时使用默认航线；命中规则的对应航线不在同步列表时停止起飞；无规则时直接使用默认航线，不要求风向数据 |
| 禁飞时间 | 每天 05:00–08:00（北京时间） | 支持添加、修改、删除多段时间，最多 24 段；结束早于开始时跨午夜；全部删除可取消此限制 |

“AI 巡查分析”中火点默认显示开启，其余五项显示关闭；当前为固定展示状态，未接入新的 AI 分析执行能力。

浓度阈值须为大于零的有限数值。前端验证输入，Rust 再次验证后原子保存。设置保存在 `monitor_settings.workspace_settings`，由监测显示与巡飞模块读取；单独修改巡飞延迟也更新该配置。PM2.5 起飞触发阈值沿用已保存的 `pm25Threshold`，默认 30 μg/m³。报告表 4 独立按实际执飞时段内的有效数据计算最高值、平均值，不读取此设置；修改起飞触发阈值不会改变报告口径。保存配置本身不会创建或提交巡飞任务。

倒计时期间，新数据恢复正常也保留原任务和原执行时间；到期仍按禁飞时段及其他执行条件复核。实际巡飞仍受数据有效期、工作环境约束；配置风向规则后，在准备任务时更新天气，并按有效预报风向优先匹配航线，计划填写和提交沿用同一条航线；计划提交回执不代表无人机已经起飞。

禁飞时段包含开始时间、不包含结束时间。数据所属小时或当前调度时间处于禁飞时段时，有效 K⁺ 或 PM2.5 超标只保存“禁飞时间”记录，不填写或提交起飞计划。禁飞结束后不补飞这些已记录的小时；新的有效超标小时继续按现有策略判断。后台在倒计时和提交前再次检查当前配置，修改时段也能阻止尚未提交的任务。手动起飞同样受当前禁飞时间限制；填写演练不提交。平台已有的定时任务由平台执行，不受本客户端限制影响。

旧配置未包含禁飞字段时按默认 05:00–08:00 读取；明确保存空时段列表后不再限制。顶部只显示简要任务状态，监测卡片下方的“巡查任务”显示人工核验提示、原始回执和最近记录。“填写核对未通过”等回执不等于已经确认电量或设备故障，具体原因由现场人工核验。

保存或删除禁飞时段时，后台在同一事务中重新检查当前禁飞状态；原时段不再适用时，将原记录保留在历史中并解除当前禁飞提醒。保存后界面立即刷新，无需等待下一轮小时同步。已跳过小时的去重标记保留，不因修改设置自动补飞。读取状态也会修复旧版本在时段删除后残留的当前禁飞提醒。

当前状态提示以当前北京时间判断：例如 05:00–08:00 在 08:00 结束后，07:00 的禁飞跳过记录只在历史中显示，不再作为顶部或巡查任务的当前禁飞提醒。最新有效数据仍为该超标小时，则提示“等待新小时数据”，说明不自动补飞、可手动执行；手动执行仍需浏览器和网站等条件通过；天气不作为 App 起飞门控。


## 清空数据

监测设置底部的“数据管理”提供“清空数据”按钮，点击后须再次确认。清空立即生效，不需要保存设置，也不会保存尚未提交的设置修改。

清空会把本机恢复到首次安装状态：清空 `monitoring.sqlite3` 中的小时监测数据、监测设置、巡查任务、天气证据、报告同步任务和同步进度；清空运行日志数据库；删除 `reports/`（包括已保存 Word 报告、照片和同步文件）、`runtime-log-exports/` 以及 `report-photo-reviews.json`。应用程序本身和浏览器插件不会删除，司空等平台上的远端任务不会被取消。

清空前必须确认。小时同步、航线同步、报告采集/保存、巡查执行和清空共用排他保护：有操作尚未结束时拒绝清空，清空期间也拒绝新操作。已保存的倒计时、已填写草稿、待核查、已提交、执飞中等任务同样阻止清空，不依赖瞬时忙碌状态。司空天气阻飞的草稿可继续刷新状态，或在司空核实已结束/取消后，通过“核查后结束任务”解除本地占用。清空前采集的报告预览失效，必须重新读取，迟到的列表结果不会恢复旧行；清空完成后工作台会回到未启动状态，但保留当前浏览器连接和网站验证状态。点击监测卡片右上角刷新按钮即可按当前图表时间范围补齐数据库缺口；也可以重新执行首批读取。清空失败会保留错误提示，便于处理占用文件或权限问题。

测试版和正式版均从 Tauri 的 `app_data_dir()` 解析这些路径。两者使用不同的应用标识和应用数据目录，因此清空只影响当前版本自己的本地数据，不会误删另一版本的数据，也不会触碰 Chrome 用户目录。

## 八方位风向规则

浏览器插件 v0.7.30 起读取司空 `/manage/api/v1/common/weather-report/v2` 当前有效时段的数值 `wind360`，传回 `windDirection`。这是**预报风向**，不是机场风速计实测风向；使用来向，不自动反转 180°。司空的 `windDir` 可能使用“东北偏东”等更细名称，App 始终按数值统一归入以下八个方向。

| 中文方向 | 角度范围（仅说明，App 不需要填写角度） |
| --- | --- |
| 北风 | [337.5°, 360°) 或 [0°, 22.5°) |
| 东北风 | [22.5°, 67.5°) |
| 东风 | [67.5°, 112.5°) |
| 东南风 | [112.5°, 157.5°) |
| 南风 | [157.5°, 202.5°) |
| 西南风 | [202.5°, 247.5°) |
| 西风 | [247.5°, 292.5°) |
| 西北风 | [292.5°, 337.5°) |

包含开始角，不包含结束角；交界点归顺时针一侧。例如 22.5° 为东北风、67.5° 为东风、337.5° 为北风；360° 统一为 0°。0° 是有效北风，缺测、空值、非数值、越界值不会被当作 0°。风速为 0 不用于推断风向。

保存仍使用已有的 `startDegrees/endDegrees/route` 数据结构，但新界面只生成上述固定区间。旧规则恰好对应完整方向时直接回显；其他自定义角度规则显示“请选择风向”并要求用户重新选择后保存，不擅自扩大、缩小或近似映射旧区间。保存前原规则保持不变。新界面禁止同一方向配置多条规则，允许多个方向选择同一航线。未配置的方向使用用户选择的默认航线；没有规则时直接使用默认航线，不要求风向数据，是否允许起飞由大疆后台决定。默认航线必须仍在已同步列表中；不使用内置航线或列表第一条替代。

起飞取风向时同时检查最近天气获取成功、回执获取时间不超过 2 分钟、机场遥测不超过 10 分钟、预报时刻不晚于当前且不超过 1 小时；人工覆盖适飞结论也不能复用失败或过期的风向。天气详情将八方位中文结果放在“司空预报”下展示。

航线设置统一为“默认航线＋可选风向规则”，不再提供固定/风向模式切换。旧 `routeSelectionMode` 字段只兼容读取，不参与选线，也不再写出；已有规则保留并优先匹配，删除全部规则即仅使用默认航线。未选择航线时仍可保存无规则的监测设置，但起飞会被默认航线检查阻止。


## 2026-10-28 清空后的界面状态

清空成功后，设置弹窗立即撤销已删除的航线列表和选择；尚未保存的阈值、起飞策略等编辑草稿保留，含风向规则的设置需重新同步并选择有效航线后保存。航线选择、航线同步和清空互斥，迟到的航线选择回执不能恢复已删除的选择。网页采集列表与巡飞报告列表一起失效并重新读取，清空前的网页列表回执不再写入当前界面。
