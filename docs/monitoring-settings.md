# 监测设置

工作台导航栏右侧的“设置”打开弹窗。修改后点击“保存设置”写入本机 `monitoring.sqlite3`，重启后保留；取消或 Esc 不保存草稿。“恢复默认”先恢复表单，仍需保存才生效。

| 设置 | 默认值 | 行为 |
| --- | --- | --- |
| 钾离子 K⁺ 阈值 | 1.0 μg/m³ | 大于阈值才视为超标；用于卡片、图表、表格提示与巡查触发 |
| PM2.5 阈值 | 30 μg/m³ | 用于自动巡查触发和可飞巡飞报告的超阈值统计 |
| 超标后延迟 | 5 分钟 | 仅在关闭人工确认、自动执行时显示和生效；可设 0–1440 整数分钟；从发现 K⁺ 或 PM2.5 有效超标数据时计时；修改用于后续任务 |
| 起飞前人工确认 | 开启 | K⁺ 或 PM2.5 超标后自动创建巡查计划；开启时等待工作人员确认，关闭后按延迟自动执行 |
| 巡查航线 | 司空航线列表同步后选择 | 设置中点击“同步司空航线”读取当前项目航线；选择结果按前缀传给计划填写和提交校验，平台生成的“副本”后缀兼容，名称不唯一时停止 |
| 航线选择方式 | 固定航线 | 可切换为“按风向选择”；按机场气象返回的气象风向（风从哪里来）匹配配置的角度区间和航线 |
| 风向航线规则 | 空 | 高级模式下至少配置一条规则；区间包含开始角、不包含结束角，支持跨越 0°，最多 16 条；规则重叠时按列表顺序首条生效；风向缺测、未匹配或对应航线不在同步列表时停止起飞 |
| 禁飞时间 | 每天 05:00–08:00（北京时间） | 支持添加、修改、删除多段时间，最多 24 段；结束早于开始时跨午夜；全部删除可取消此限制 |

“AI 巡查分析”中火点默认显示开启，其余五项显示关闭；当前为固定展示状态，未接入新的 AI 分析执行能力。

浓度阈值须为大于零的有限数值。前端验证输入，Rust 再次验证后原子保存。设置保存在 `monitor_settings.workspace_settings`，监测显示、巡飞与报告模块共同读取；单独修改巡飞延迟也更新该配置。保存配置本身不会创建或提交巡飞任务。

实际巡飞仍受数据有效期、工作环境与天气检查约束；高级航线模式在起飞前天气复核通过后确定本次航线，计划填写和提交沿用同一条航线；计划提交回执不代表无人机已经起飞。

禁飞时段包含开始时间、不包含结束时间。数据所属小时或当前调度时间处于禁飞时段时，有效 K⁺ 或 PM2.5 超标只保存“禁飞时间”记录，不填写或提交起飞计划。禁飞结束后不补飞这些已记录的小时；新的有效超标小时继续按现有策略判断。后台在倒计时和提交前再次检查当前配置，修改时段也能阻止尚未提交的任务。手动起飞与天气强制起飞同样受当前禁飞时间限制；填写演练不提交。平台已有的定时任务由平台执行，不受本客户端限制影响。

旧配置未包含禁飞字段时按默认 05:00–08:00 读取；明确保存空时段列表后不再限制。顶部只显示简要任务状态，监测卡片下方的“巡查任务”显示人工核验提示、原始回执和最近记录。“填写核对未通过”等回执不等于已经确认电量或设备故障，具体原因由现场人工核验。

保存或删除禁飞时段时，后台在同一事务中重新检查当前禁飞状态；原时段不再适用时，将原记录保留在历史中并解除当前禁飞提醒。保存后界面立即刷新，无需等待下一轮小时同步。已跳过小时的去重标记保留，不因修改设置自动补飞。读取状态也会修复旧版本在时段删除后残留的当前禁飞提醒。

当前状态提示以当前北京时间判断：例如 05:00–08:00 在 08:00 结束后，07:00 的禁飞跳过记录只在历史中显示，不再作为顶部或巡查任务的当前禁飞提醒。最新有效数据仍为该超标小时，则提示“等待新小时数据”，说明不自动补飞、可手动执行；手动执行仍需浏览器、网站和天气等条件通过。


## 清空数据

监测设置底部的“数据管理”提供“清空数据”按钮，点击后须再次确认。清空立即生效，不需要保存设置，也不会保存尚未提交的设置修改。

清空会把本机恢复到首次安装状态：清空 `monitoring.sqlite3` 中的小时监测数据、监测设置、巡查任务、天气证据、报告同步任务和同步进度；清空运行日志数据库；删除 `reports/`（包括已保存 Word 报告、照片和同步文件）、`runtime-log-exports/` 以及 `report-photo-reviews.json`。应用程序本身和浏览器插件不会删除，司空等平台上的远端任务不会被取消。

清空前必须确认。正在进行小时同步或巡查执行时会拒绝清空，避免并发写入；清空完成后工作台会回到未启动状态，但保留当前浏览器连接和网站验证状态。点击监测卡片右上角刷新按钮即可按当前图表时间范围补齐数据库缺口；也可以重新执行首批读取。清空失败会保留错误提示，便于处理占用文件或权限问题。

测试版和正式版均从 Tauri 的 `app_data_dir()` 解析这些路径。两者使用不同的应用标识和应用数据目录，因此清空只影响当前版本自己的本地数据，不会误删另一版本的数据，也不会触碰 Chrome 用户目录。
