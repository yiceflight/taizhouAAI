## 需要优先修复

### F1 · P1 · PM2.5 单指标任务被插件拒绝

位置：`src-tauri/src/flight.rs:571`；`extension/src/flight-plan.js:8`、`:16`、`:28`、`:168`、`:320`。

当最新有效小时 K⁺ 为 NULL、PM2.5 超阈值时，Rust 会生成 `PM2.5超标巡查-20261027-10`。插件的填写参数、提交参数、页面内提交、状态查询都只允许“钾离子超标巡查/手动巡查”等旧名称。填写入口立即返回“司空任务参数无效”，所以任务不能进入计划填写，更不会执行起飞。

已复现：将合法事件编号、航线和上述后台任务名直接交给 `validatePlanJob`，本应接受却抛错。现有测试只验证旧任务名，未覆盖跨 Rust/JS 的新名称契约。

修复方向：统一自动任务命名契约，并同步准备、提交、状态查询和 UI 来源识别；保留对填写演练不可提交的限制。另一个同源显示问题：K⁺ 有正常值但只有 PM2.5 超标时仍命名为“钾离子超标”，报告事件原因也仍可能写“由K⁺监测触发”。应按实际超标指标生成原因。

### F2 · P1 · 航线前缀有歧义时后台会自行选中一条

位置：`src-tauri/src/flight.rs:128`、`:168`、`:1158`。

已配置的原航线不再精确匹配、但同步列表有多条同前缀副本时，`best_route_match` 使用 `max_by_key` 选名字最长的候选；等长时也会直接选中一个。风向规则匹配和默认航线同步恢复都使用这一逻辑。后台随后把选中的完整名称交给插件，插件自己的唯一性校验不能再识别后台已经丢弃的其他候选。

已复现：规则“巡查航线”，候选“巡查航线-副本(1)”及“巡查航线-副本(2)”，实际返回第二条而非歧义错误。这与当前文档中“多个不同后缀但同前缀的候选仍按歧义处理”不一致，可能选错航线。

修复方向：精确匹配也检查唯一性；仅对明确允许的副本后缀做归一化，多个匹配应停止并要求重新选择。不能靠最长名称认定航线身份。

### F3 · P1 · 清空数据未保护已经提交或正在执飞的任务

位置：`src-tauri/src/data_reset.rs:77`；`src-tauri/src/flight.rs:820`、`:980`；`src-tauri/src/flight_report.rs:1483`。

`clear_all_data` 只检查瞬时 `Monitor.busy` / `Flight.busy`，未检查持久化任务是否处于 ready/submitted/uncertain/flying/paused 等未处理状态。`Flight.busy` 是调度函数执行锁，提交返回后会释放，后续飞行状态轮询使用另一个 `status_gate`。因此无人机尚未结束或结果待核查时，清空仍可删除当前任务、历史回执和按小时去重标记，而远端任务不会取消。后续恢复航线配置并发起任务时，本地已无法拦截与原任务重叠的起飞。

报告采集和 `spawn_blocking` 保存也不占这两个 busy 标记，存在清空删除报告目录与报告保存/同步回写并发的路径。监测 busy 的两次读取本身也不是与监测启动共享的排他锁。

验证方式：代码调用链确认；没有对用户数据库执行清空，也没有用真实飞行验证此问题。

修复方向：正常清空必须拒绝未结束/待核查任务，或显式保留其防重复状态；为同步、报告写入和清空建立共同的生命周期/排他机制。后台回执应带重置代次，防止清空后的迟到写入。不可只增加前端按钮禁用。

## 数据与报告问题

### F4 · P2 · 手动生成含可飞数据的报告丢失本机任务关联

位置：`src/components/FlightReportPanel.tsx:324`；`src-tauri/src/flight_report/evidence.rs:64`。

手动采集请求仅在 `withoutAirData` 分支发送 `localEventId`；正常可飞分支只发送嗅探会话和标签。即使 UI 已识别本机事件，后台得到的关联仍为 None。报告证据只在收到事件 ID 后读取对应的本机触发与飞行记录，因此手动重新生成可能丢失原本保留的本机来源证据。自动报告路径则会发送该字段，形成自动/手动行为不一致。

已用组件测试复现：选择已关联本机已完成事件的含可飞报告，点击“重新生成报告”→“自动匹配并读取资料”，请求中 `localEventId` 为 undefined。

修复方向：将 `localEventId` 放在两个采集分支的公共字段中，并验证重新生成后仍能取得同一事件证据。

### F5 · P2 · 历史任务航线被当前默认航线覆盖显示

位置：`src/components/FlightReportPanel.tsx:401`；`src/App.tsx:88`。

没有关联 DJI 任务的记录，渲染直接使用父组件传入的当前航线 `configuredRoute`，完全忽略该行已有的 `localEvent.route`。修改默认航线或当前任务换线后，过去任务的显示随之改变；未知航线也会被显示为当前默认值。

已用组件测试复现：历史事件记录“历史实际航线”，当前默认设置“当前默认航线”，历史行显示后者。

修复方向：优先使用该航次的 DJI 航线，再使用该事件保存的航线；都没有时显示“航线未记录”，不要用今天的默认设置补写历史事实。

### F6 · P2 · 刷新短时间窗口会跳过离线期间待补历史

位置：`src-tauri/src/monitoring.rs:144`、`:210`、`:266`、`:287`。

自动补读和手动图表刷新共用 `persist`，该函数无条件把 `query_through` 改成当前请求结束时间。离线很久后，本来应按最多 7 天的窗口逐段补回；如果中途点击“今天/24小时”刷新，游标会直接跳到今天，下一轮自动同步只回看最近 48 小时，较早缺口失去自动续传入口。

已复现：保存 20 天前的游标，然后按“今天”窗口入库，下一轮起点从应继续补读的旧日期跳到当前日前 2 天。复现不依赖真实平台，使用内存 SQLite 和本地当前日期。

修复方向：将自动连续补读游标与临时展示窗口刷新分离；只有覆盖连续补读区间的批次才推进该游标。
