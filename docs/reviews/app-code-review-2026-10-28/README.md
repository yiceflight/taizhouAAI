## 应修复问题

### F1 · P2 · 大于 300 条的分批任务同步无法清除平台已删除记录

位置：`src-tauri/src/flight_report.rs:679–710`；`extension/src/dji-tasks.js:158–180`。

删除旧缓存的条件要求“单个响应内的任务数等于平台总数”。插件一次最多读第一页和另外五页，每页 50 条。平台总数超过 300 时，即使多批已经读完整个历史，也没有任何一批能满足这个条件。后台没有保存本轮扫描所见的完整 ID 集合，因此平台删除/过期的任务会一直留在本机表中；六小时重扫也不能清除它们，任务数和列表会持续不一致。

复现：先缓存一个后来被删除的任务，再模拟平台当前 301 条任务的完整两批同步。第一批读取 1–300；第二批刷新 1–50 并读取最后一条，明确返回扫描完成、总数 301。实际本机仍有 **302** 条。

建议：为每次完整扫描建立扫描代次，记录本轮出现的任务 ID，仅在完整且成功的扫描结束后清除未出现的旧平台缓存。中途失败、游标重置或总数变化时不可凭单批缺行删除；本地已生成报告文件继续保留。

### F2 · P2 · 手动任务优先绑定旧 K⁺ 小时，忽略更新的 PM2.5 小时

位置：`src-tauri/src/flight.rs:1304–1313`。

手动任务和演练创建时先查最新非空 K⁺，只有数据库完全没有 K⁺ 时才查 PM2.5。自动触发和当前界面则采用“任一指标有效的最新小时”。例如 10:00 有 K⁺，11:00 的 K⁺ 缺测但 PM2.5=80，用户在最新 PM2.5 预警下立即执行，事件的 `sourceHour` 却写成 10:00，历史记录中的“绑定小时数据”与当时监测上下文不符。

复现：内存数据库保存上述两个小时，创建真实手动类型的事件，实际 `sourceHour=10:00`，预期为 11:00。

建议：使用与自动触发一致的 `(potassium IS NOT NULL OR pm25 IS NOT NULL)` 条件，按时间倒序取一条。这里是关联/审计错误，不将其夸大为已证实的重复起飞或阈值计算错误。

### F3 · P2 · 清空成功后设置仍显示已删除航线，网页采集列表也不失效

位置：`src/components/SettingsDialog.tsx:31–43`；`src/components/CapturePanel.tsx:4–9`；`src/App.tsx:55–58`、巡查任务页的组件传参。

设置弹窗的 `routes` 只在挂载时从 props 初始化。清空数据库后，父组件即使已经传入空航线和空选择，仍显示旧航线“已选”。用户可能以为航线配置仍然有效；旧风向规则也会基于残留列表通过前端校验，但实际数据库已没有航线，随后起飞会被后台阻止。

复现：打开带航线的设置，模拟清空成功并由父组件传入空列表，弹窗已显示“本地数据已清空”，下拉框却仍保留原航线。

同一清空链还有一个代码确认的残留：`CapturePanel` 仅在首次挂载时读取网页采集记录，不接收重置代次，也没有被重新挂载。文件已删除后，原列表和计数仍可保留，点击“查看”才报文件不存在。巡飞 Word 列表已有重置代次处理，网页采集列表尚未接入。本子项由调用链确认，未操作真实用户数据复现。

建议：清空后使航线缓存、网页采集列表和迟到回执统一失效；可以保留尚未保存的设置编辑草稿，但不能把已删除的持久化航线继续显示为有效。现有测试明确保留编辑草稿，因此本轮不把“编辑框没有恢复默认值”单独列为 bug。
