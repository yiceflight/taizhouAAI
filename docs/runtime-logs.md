# 运行日志

工作台的「运行日志」页读取本机后台写入的持久化记录。窗口隐藏或最小化时无需打开该页。此功能不能补录安装之前的行为。

## 使用

- 按北京时间、级别、类别或关键词筛选；支持任务 ID、浏览器请求 ID 和启动会话 ID 搜索。
- 最新页每 5 秒读取一次；查看更早记录时暂停自动刷新，避免翻页跳动。每页 100 条。
- 日志列表直接以中文显示关键信息和状态摘要；完整结构化记录仍可通过「导出筛选结果」留存。
- 「导出筛选结果」导出当前筛选条件下的全部留存记录，不局限于当前页。JSONL 按写入顺序排列，每行一条 JSON；`at` 是 Unix 毫秒时间，可按 UTC 或北京时间转换。
- 导出文件位于应用数据目录的 `runtime-log-exports` 子目录，可点击「打开导出文件夹」。手动导出文件保存在本机。正式版另有重要异常自动邮件上报，见 [诊断邮件](diagnostic-email.md)。

## 记录覆盖

| 类别 | 记录 |
| --- | --- |
| 客户端 | 启动版本、系统、进程及启动会话，工作台启动结果，正常退出，配置观测；系统从锁定或休眠恢复后的天气、运行状态和补同步检查 |
| 窗口 | 每 2 秒观测可见、最小化、焦点变化；关闭至托盘、从托盘恢复的请求另行记录 |
| 后台存活 | 每分钟一条，包含窗口状态、监测开关、运行就绪状态、最近同步与最新源数据时间 |
| 浏览器 | 连接可用性变化、会话数量、插件版本、错误；任务请求、实际交付、结果或失败及耗时，使用同一请求 ID 串联 |
| 网站验证 | 各网站状态及原因变化，整体运行状态与各能力的就绪变化 |
| 监测 | 同步开始、数据写入范围和条数、同步结果；定时同步因尚未启动、监测关闭或运行条件不满足而跳过 |
| 天气 | 获取开始、成功的观测时间和平台结论、失败原因 |
| 巡查 | 同步后的触发评估、条件未就绪跳过、调度及状态同步错误与恢复；每 2 秒观测当前任务 ID、状态及错误变化 |
| 报告与设置 | 网页报告生成、巡查报告采集和保存的开始及结果；运行设置保存结果 |

浏览器任务「返回结果」只确认插件回执已返回，业务是否完成还应结合监测写入、报告保存、网站验证和巡查状态记录。日志不改变任务执行、起飞许可、重试或网站验证策略。

## 最小化问题排查

1. 找到 `window.state` 中 `minimized: true` 或 `visible: false` 的记录。
2. 查看此后的 `app.pulse`：证明该时刻后台日志观察器仍能执行，不能单独证明监测或巡查成功。
3. 结合 `sync.started`、`sync.persisted`、`sync.finished`、`sync.skipped` 和浏览器请求 ID 判断实际执行结果。
4. `bridge.state`、`site.*`、`workspace.state` 记录叹号相关状态变化和恢复。
5. 观测循环间隔超过 90 秒或系统时间倒退时，记录 `app.observation_gap`。休眠、进程阻塞、系统时间调整都可能产生间隔，日志不推断唯一原因。强制结束进程或断电可能没有退出记录。

## 存储与边界

- 独立 SQLite 文件 `runtime-logs.sqlite3`，不改变业务数据表；每次启动有独立会话 ID，跨重启保留历史。
- 保留最近 30 天且最多 20,000 条，以先达到的限制为准。导出文件不自动清理。
- 状态观测周期为 2 秒，短于采样周期的中间状态可能不被观测到。任务请求、交付、回执和同步结果直接在执行路径记录。
- 按部署要求，运行日志保留错误原文、完整 URL、结构化详情和浏览器任务参数，不再自动脱敏或截断文本/数组。不会主动读取邮箱密码、OSS 凭据文件、浏览器 Cookie 库、截图或报告正文；已进入错误文本或任务参数的内容按原样记录。旧版已经脱敏的历史无法恢复。
- 存储失败不将业务操作改判为失败；日志页明确报告写入/读取异常。日志初始化失败时本次启动无法记录，需要排除存储问题后重启。
- 浏览器界面验收使用模拟数据；自动测试覆盖留存、重启读取、筛选、游标、脱敏、存储失败与界面交互。Windows 真机最小化、休眠恢复和真实插件断连需在安装包含此功能的新客户端后核验。

## 只读并发验证（2026-10-31）

插件 v0.7.35 的只读检查没有并发数量上限，可在串行任务执行期间继续接收。`job.started` 到 `job.delivered` 是排队阶段；交付后才计算执行期限。`elapsedMs` 仍表示从请求到结果的总耗时。排队超时会明确说明尚未执行网站检查，不能据此判断登录失效。

本次自动测试覆盖 40 个只读检查绕过阻塞任务、后续心跳继续领取检查、共享标签页连接/可见性引用计数、独立交付期限和串行提交互斥。开发实例实际心跳已确认 v0.7.35；12:03:28 三站检查在同一轮交付并返回，12:03:30 三站均为 ready。这是开发实例验收记录，不代表正式版发布或 Windows 验收。

## 自动诊断邮件

正式版复用邮件发送配置，将重要异常的详细日志发送到固定维护邮箱。持久化队列、附件范围、重试和已知边界见 [诊断邮件](diagnostic-email.md)。前端全局异常与 React 错误会写入运行日志；正式版 Rust panic 尽力落盘，下次启动导入上报。
