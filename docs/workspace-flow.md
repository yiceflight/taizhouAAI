# 工作环境与监测工作台

## 使用顺序

1. 启动桌面客户端。未连接兼容插件时，只显示插件配置向导；历史报告仍可查看。
2. 安装或重新加载客户端附带的 Chrome 插件（最低 v0.6.0）。连接异常会区分插件未连接、旧版本、多浏览器会话、客户端端口冲突。
3. 在 Chrome 登录江苏大气站、大疆司空、可飞平台。三个网站的身份或业务接口都通过验证，才允许继续。
4. 三个网站验证全部通过后，自动读取首批数据并进入监测总览；读取失败时显示错误，保留“读取数据并开始监测”按钮供手动重试，不循环重试。查看历史报告时不会强制跳走。

每次重新启动客户端都重新验证工作环境，通过后自动开始监测，不沿用上次进程的登录验证结果。数据和历史报告保留；已启动工作台的连接恢复不会再次执行启动操作。

## 状态与恢复

- 插件：必须有且仅有一个兼容会话，没有本地连接服务错误。
- 网站：就绪、需登录、无权限、需打开业务页、检测异常分别显示。网络错误不会被误判成登录成功。
- 每秒检查插件连接及页面变化，连接成功或业务页变动后尽快验证；正常状态每 45 秒复查，异常状态每 10 秒复查。三站检查一起排队，在同一轮插件心跳派发，插件仍串行使用 CDP，避免逐站各等一次 5 秒心跳。整批最坏串行耗时计入检查超时。验证结果最多有效 120 秒，并绑定浏览器会话、标签页和页面 URL。界面每 2 秒读取状态。
- 三个网站任一未就绪，停止发起新的自动同步、手动同步、巡查填写或外部报告资料采集；正在保存的本地成果、历史报告查看不受影响。
- 恢复后保留当前工作位置和巡查提醒。原计划入口定位插件保存的原草稿标签页，不重新创建计划。
- 数据时间与同步时间分开显示。超过 3 小时或指标缺测时显示警告；旧数据和缺失的 K⁺ 不触发巡查。

## 页面组织

- 监测总览：整体运行状态、三站状态、最新数值、数据质量、24/72/168 小时时间范围和图表/表格。
- 巡查任务：准备进度、待人工确认、失败重试和提醒归档。归档不表示飞行已经执行，也不取消浏览器草稿。
- 报告与成果：历史巡飞报告；新建采用“选任务 → 核对资料 → 生成 Word”。原网页采集功能保留在折叠区。
- 工作环境：安装与登录准备、逐站验证结果和恢复入口。

## 检测边界

固定只读适配器位于 `extension/src/site-health.js`：

- 江苏：使用时间序列页面现有的 API 客户端读取泰州市指标目录。
- 可飞：通过当前浏览器会话读取历史任务列表，必须取得成功业务返回。
- 司空：复用已加载前端的 HTTP 客户端，调用其现有 `/manage/api/v1/users/current` 身份接口，并要求当前在指定泰州项目路径。平台前端模块变化时会返回检测异常，不放行。此检查不代表设备在线、具备起飞权限或媒体资料已经上传完成。

适配器不读取或返回密码、Cookie、Token 或浏览器存储中的平台凭据。司空身份接口响应只在页面内判断，客户端只接收状态、说明和页面 URL。飞行仍只填写，不提交、不起飞。

## 本次验证

- `pnpm build`
- `pnpm test`：扩展适配器、来源验证、登录页、401/403、业务失败、超时/网络错误。
- `pnpm test:ui`：准备步骤、操作禁用、缺测/过期数据、历史报告访问。
- `cargo test --lib`：缓存过期、页面/会话变化、插件断连/多会话/旧版本、原监测与报告功能。
- macOS Tauri 客户端实际验证未连接插件时的准备页、业务入口锁定，以及原有 3 份历史巡飞报告正常列出；本地 debug 应用已打包。
- `/tests/fixtures/workspace.html` 仅在 Vite 开发服务提供，用明确标注的模拟数据检查全部界面状态；不会进入正式构建，也不调用业务网站。不能把模拟场景作为三站真实登录成功的证据。

三个平台的新版检测适配器仍需在重新加载 v0.6.0 插件后做真实账号联调；没有通过检测时客户端会保持阻止状态。
