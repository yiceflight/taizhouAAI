# Chrome 桥接插件

插件把本机 Tauri 客户端和三个业务网站连接起来。它只在客户端下发任务时读取已授权页面，不读取 Cookie、localStorage、口令或访问令牌，也不执行任意脚本。

## 使用正式版

1. 使用 Chrome 120 或以上版本，在 `chrome://extensions` 开启开发者模式。
2. 在客户端「运行状态 → Chrome 插件」复制插件目录，选择「加载已解压的扩展程序」。
3. 保持 Chrome 和客户端运行。插件通常在 5 秒内建立心跳，超过 75 秒未收到心跳时客户端会显示未连接。
4. 客户端升级后，在扩展管理页重新加载客户端提供的目录。不要继续使用旧安装位置的副本。

正式版使用 `127.0.0.1:14520` 和正式插件 ID。完整的版本要求与来源见 [`bridge-config.json`](../bridge-config.json)。

## 开发与测试版

开发运行使用独立的应用身份、端口和数据库：`com.taizhou.aai.dev`、`127.0.0.1:14521`。执行 `pnpm dev:client` 后，在当前系统 Chrome 中加载它显示的 `extension-dev/` 目录；所有平台页面和后台任务都会复用当前 Chrome 的登录态。

显式测试包使用 `pnpm build:test-client`。普通 `pnpm tauri build --debug` 仍是正式版，不能用来代替测试包。正式版和测试版通过应用标识、端口和插件 ID 区分，并统一使用当前系统 Chrome。

环境边界、构建规则和验收步骤见 [`docs/environment-isolation.md`](../docs/environment-isolation.md)。

## 支持的任务

- 页面健康检查和登录状态验证。
- 江苏大气站泰州市 K⁺ 与 PM2.5 小时数据同步。
- 司空巡查计划准备、提交前核对和受客户端门控的提交。
- 司空泰州项目航线列表只读同步，按用户选择的航线前缀填写并在提交前复核。
- 机场天气、巡查状态和巡飞报告资料读取。
- 用户点击后生成受限范围的网页快照报告。

业务结果以客户端的同步、天气、巡查和报告记录为准。插件返回任务回执只表示桥接请求结束，不表示远端业务已经完成。

巡飞报告媒体采集按任务隔离：插件为每个报告任务创建后台司空媒体页，最多并行处理 3 个任务，并在成功、失败或超时后关闭自己创建的页面。用户原本打开的司空页面不会被关闭；任务列表同步不再创建共享媒体页。

## 本地协议

- `POST /heartbeat`：发送会话和插件版本，接收客户端下发的任务。
- `POST /complete`：返回任务结果；客户端校验任务所属会话。

客户端严格校验 Host、Origin、请求头和业务 URL。插件只在授权业务标签页上保持临时调试连接，采集完成或失败后释放连接。调试连接、页面跳转、网络错误和登录失效都会返回明确失败，不会静默切换到另一版端口。

## 开发流程

插件源码只修改本目录；测试构建会从这里生成 `extension-dev/`，不要直接编辑生成目录。修改后重新运行对应客户端并在对应 Chrome 中重新加载插件。端到端验收需要同时确认客户端、插件 Service Worker、业务页面和远端任务结果，自动化测试不能替代真实 Chrome 或现场飞行验证。

## 托管标签组

插件 v0.7.40 起，App 自动打开的业务页统一归入蓝色「泰州监测 · App 托管」标签组；开发版使用独立的「泰州监测 · App 托管（开发版）」组。后台查找只复用该组的页面，用户另行打开的平台页不会仅因网址相同而被接管。已有任务保存的页面在再次使用时会归组。所有页面仍共用原 Chrome 配置中的登录态。

从 App 打开平台也通过桥接插件执行，插件未连接或过旧时会提示修复连接，不会绕过分组打开普通页面。标签组用于区分用途，Chrome 仍允许手动关闭；关闭后下次需要时会重建页面和分组，原有飞行草稿与提交防重规则不变。
