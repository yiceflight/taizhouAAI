# Chrome 浏览器桥接插件

插件 v0.2.0 连接本机桌面客户端，报告三个业务网站的页面状态，并在用户点击「生成报告」时通过 Chrome CDP 读取选定页面的正文和 HTML 表格。不会主动操作业务数据，不读取 Cookie、浏览器存储或输入框值，也不接受任意脚本执行消息。

## 安装与升级

1. 使用 Chrome 120 或以上版本，打开 `chrome://extensions` 并开启开发者模式。
2. 在桌面客户端底部「Chrome 插件」复制插件完整路径。
3. 点击「加载未打包的扩展程序」，选择该路径。macOS 可在目录选择器按 `⌘⇧G` 粘贴路径；Windows 按 `Ctrl+L`。
4. 客户端升级后，在扩展管理页点击本插件「重新加载」。本次从 0.1.0 升到 0.2.0 引入固定插件 ID，Chrome 会保留一个停用的旧条目；使用已启用的 0.2.0 条目即可。
5. 保持 Chrome 和客户端运行，通常 5 秒内连接；后台休眠后由 Chrome alarm 恢复，可能需要 30 秒以上。超过 75 秒未收到心跳，客户端显示未连接。

「打开文件夹」打开插件上一级目录，便于拖入整个 extension 文件夹；「复制路径」仍是插件完整路径。

## 采集报告

打开并登录业务网站，在客户端「报告列表」选择具体页面，点击「生成报告」。报告保存在客户端应用数据目录的 `reports/` 下，重启后保留。点击「查看」生成并打开独立 HTML，可打印或保存 PDF；「报告目录」可找到 JSON 原始记录和已经打开过的 HTML。

状态「已打开」仅表示 Chrome 标签页存在，不代表登录状态、接口健康或业务数据完整。报告只记录当前页面的可见文字和 HTML 表格，不遍历分页、不读取 canvas 图表内部数据、不生成监测等级或专业结论。正文上限 10 万字符，最多 20 张表、每表 200 行、每行 30 列，表格文本累计最多 20 万字符；截断会写入报告。总表格载荷过大时仅保留正文并标记截断。

v0.5.0 新增固定的巡飞报告适配器：读取可飞历史任务列表、完整 PM2.5 与坐标序列；从指定司空项目 Immediate-Media 文件夹逐张下载照片记录对应的原始 JPEG/PNG。不会读取 Cookie、storage、口令或访问令牌，也不会返回临时签名资源地址。普通网页采集仍只读取正文与表格。来源、任务匹配和数量限制见 [巡飞快报](../docs/flight-report.md)。

## 本地协议

正式客户端监听 `127.0.0.1:14520`，仅接受正式插件 origin `chrome-extension://knpgppgofegbnimjoahnifpmhgmgnicf`。`tauri dev` 监听 `127.0.0.1:14521`，仅接受自动生成的 `extension-dev/` 插件（origin `chrome-extension://lgallibgppbepolgogkfbebphjiiejkn`）。两版插件可同时安装；从对应客户端复制路径，开发插件名称带“开发版”。客户端严格校验对应的 Host、Origin、请求头和业务 URL，不扫描或回退到另一版端口。固定 public key 不属于机密，origin 校验用于浏览器边界，不用于防御已能控制本机的其他进程。

客户端升级不会代替 Chrome 重新加载未打包插件。若客户端顶部提示“必须更新浏览器插件”，在 `chrome://extensions` 找到对应插件并点击“重新加载”。仍显示旧版本时，请重新选择该客户端提供的插件目录（不要继续加载旧安装位置的副本）。收到兼容版本心跳后提醒自动消失，网站验证通过后恢复业务操作。

端口与插件身份隔离不等于业务浏览器页面隔离；同时操作同一标签页仍可能争用 Chrome debugger。需要同时运行正式业务与开发采集时，使用不同 Chrome 配置文件及各自插件、业务标签页。

- `POST /heartbeat`：发送会话 ID、插件版本、业务页面元数据，接收指定页面采集任务。
- `POST /complete`：返回已下发任务的结果或错误，校验任务所属会话。
- 页面快照只在用户发起采集后生成；插件在一个已授权业务标签页上保持调试连接，避免 Chrome 调试提示反复出现。临时调试连接在采集完成后释放，失败不生成报告。
- 浏览器实例 ID 保存在插件本地存储，重载插件或浏览器重启后沿用，避免旧会话导致重复页数。
- 客户端重启后等待插件重新心跳即可恢复；端口占用显示错误，不假报连接成功。

插件权限限于 debugger、tabs、alarms、storage，业务网站保持原有三个范围，新增本机 HTTP 用于连接客户端。Chrome 可能显示调试提示；开发者工具占用调试连接时，采集会报错，请关闭对应标签页的开发者工具后重试。

## v0.7.4 启动验证与 Chrome 提示

客户端启动后优先验证可飞；如果没有可飞标签页，会在后台只打开一次历史任务页，不切换当前标签页。插件只在已授权的业务标签页保留一个调试连接，让 Chrome 原生调试提示保持稳定；离开授权网站或关闭该标签页后会切换或释放连接。用户点击 Chrome 提示中的“取消”后，插件不再自动重连；点击插件图标可恢复。更新客户端后仍需在 `chrome://extensions` 重新加载开发版或正式版对应插件。

## v0.3.0 小时同步

新增客户端下发的 `jiangsu-hourly` 任务（`startTime` / `endTime`，北京时间整点）。在江苏大气站已登录页面执行，固定查询泰州市 K⁺ 小时混合数据，使用平台自身认证 API 客户端，不向桌面传输身份凭据。返回按小时对齐、经过校验的指标数据；任务失败经原 completion 通道报告。更新后请在 Chrome 扩展管理页重新加载插件。

## v0.4.0 司空计划填写

新增固定 `dji-prepare` 任务，仅在用户指定组织/项目新建独立标签页，按视频选择航线和机场并填写；`submit` 必须为 `false`，不会点击最终确认。此项是对开头旧版「不会主动操作业务数据」说明的补充：现在可以修改尚未提交的计划表单，不提交业务记录或飞行命令。不会读取或传输凭据。具体规则、去重与错误处理见 [司空计划准备](../docs/flight-plan-preparation.md)。

## v0.7.0 巡飞提交

新增独立 `dji-submit`：仅接收后台生成的真实巡飞事件，在原计划页重新核对固定配置后点击一次最终确定。事件提交标记持久化，回执不明确时不重试；演练仍只填写。需要在客户端明确开启自动巡飞，并遵守共享的延迟/人工确认配置及天气门控。手动任务可绕过 K⁺ 超标条件。实现与验收边界见 [无人机调度](../docs/drone-dispatch.md)。

## v0.7.3 提交前核对

自动提交前在司空计划页面右侧显示计划字段、回读通过后的绿色状态和 30 秒倒计时。期间点击“取消本次作业”会取消客户端持久任务；倒计时结束时若面板已消失或字段未全部通过，不会点击最终确定。人工确认模式与填写演练仍不自动提交。需要重新加载 v0.7.3 插件并使用匹配的客户端版本。

## 启动自动准备网站（v0.7.8）

客户端在插件连接后自动补开缺失的三个平台页面：江苏大气站地图入口、大疆司空泰州项目、可飞历史任务。插件打开前重新查询现有标签页，复用已打开或正在加载的页面，并仅在后台创建缺失页面。每个平台每次客户端启动最多尝试补开一次；手动重新验证可重试。完成登录后自动复查。新验证任务只允许固定平台地址，不执行计划填写或提交。


v0.7.8 取消江苏时间序列组件/路由依赖，直接使用根实例的全局 `$Ajax` 读取目录和小时数据。已有同源页面逐一验证，旧登录或失败页面不覆盖另一个成功页面；同步使用验证通过的页面。升级需重新加载插件及新版客户端。

v0.7.9 保留查询范围内平台返回的尾部空值小时及整批空值小时，最新数据时间不再停留在最后一个非空 K⁺ 值。空值保存为 NULL，显示“暂无数据”且不触发自动巡查；更新后需在 Chrome 扩展管理页重新加载插件。

v0.7.10 读取司空最终确定后的二次弹窗，回传天气阻飞、执行设备和平台风速等正文；不点击二次“执行”。待核查任务也会只读检查本任务的原草稿（必须匹配计划名），将现存阻飞原因回传到“司空核查”，不重复提交。

v0.7.11 将司空“任务执行（进度）”归一为客户端“执行中”，修复实际飞行时仍显示待核查的问题。提交回执仅核对唯一的同名计划行，允许设备卡片重复显示任务名；只有设备卡片或存在多个同名计划行时仍不确认、不重试。重新加载插件后，已有待核查任务可通过自动状态轮询恢复。
